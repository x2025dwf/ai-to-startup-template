## Work sessions

### Session 1 — Initial development

- Goal for this session: Create a website that helps university students organize their academic schedules.
- Key prompt we gave Copilot: "Build a fully functional student planning website called StudySync using the existing starter files."
- What worked: Copilot created the homepage, dashboard, weekly schedule and assignment tracker. The website used a navy-and-white colour scheme and a simple layout.
- What broke, and how we fixed it:** No specific functional failures were recorded during initial development.
- Committed? Not recorded.

### Session 2 — Website functionality

- Goal for this session: Develop the features that make StudySync useful for university students.
- Key prompt summary: Include an editable weekly schedule, assignment tracker, automatic study planner, calendar and progress dashboard.
- What worked: Students could add, edit and delete classes and assignments. The automatic planner considered deadlines, priorities and available study time. Information was saved using localStorage.
- What broke, and how we fixed it: The limitations of browser storage were addressed by keeping the prototype focused on individual users rather than introducing accounts and cloud storage.


### Session 3 — Testing the website

- Goal for this session: Make sure the main features of StudySync worked properly.
- Key prompt summary: Include fictional sample classes and assignments and a reset sample data feature.
- What worked: The sample schedule and reset sample data button worked successfully. JavaScript syntax and the main planner interactions were also checked.
- What broke, and how we fixed it: A browser was unavailable in the development workspace. Alternative testing methods were used to check the functionality of the website.


### Session 4 — Publishing and documentation

- Goal for this session: Prepare StudySync for online access and complete the project documentation.
- Key prompts: "Write the business case" and "write the project log."
- What worked: The business case and project documentation were created. GitHub Pages was used as the publishing method.
- What broke, and how we fixed it: Finding the correct GitHub Pages settings was difficult because the custom domain section caused confusion. Working through the repository settings helped clarify that purchasing a domain was unnecessary.
- Committed? Not recorded.

## Reflection

### 1. What surprised you most about building software with AI?

The most surprising part of building StudySync was how quickly AI could turn a simple business idea into a working website. Before using Copilot, creating a website with this many features seemed like something that would require a lot of coding knowledge. Copilot was able to create a dashboard, calendar, assignment tracker and study planner from written instructions.

This shows how AI can make entrepreneurship more accessible. Someone with a business idea can create a prototype without having to spend thousands of dollars hiring software developers. However, having a working website does not automatically mean that the business will be successful. Entrepreneurs still need to understand their customers and determine whether their product solves a real problem.

### 2. Which parts were easy, and which were hard? Why do you think that is?

Creating the basic website was one of the easier parts because Copilot could generate the code based on the instructions it received. Adding features such as assignment priorities, sample schedules and progress tracking was also possible through written prompts.

One of the harder parts was working with GitHub Pages. Finding the correct settings took longer than expected, especially when trying to understand whether a custom domain was required.

Testing the website was also important because AI-generated code is not guaranteed to work perfectly. This demonstrates that AI can reduce the amount of technical knowledge needed to build software, but human judgment and problem-solving are still important.

### 3. If a competitor had the same AI tool, how long would it take them to copy your site?

A competitor using the same AI tools could probably recreate the basic version of StudySync within a few days or weeks. Most of the features are not unique, and similar calendars and assignment trackers already exist.

For this reason, the website itself would not create a strong competitive advantage. StudySync would need to develop other advantages, such as university partnerships, Moodle integration and a strong reputation among students.

This relates to the VRIN framework because although StudySync provides value, its basic features are not rare, difficult to imitate or non-substitutable. Building relationships with universities and understanding what students need could help create a stronger competitive advantage over time.
